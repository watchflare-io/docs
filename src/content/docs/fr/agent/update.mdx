## Linux

La commande `update` est dans le binaire. Elle interroge l'API GitHub, télécharge depuis `get.watchflare.io`, vérifie le SHA-256, puis confie le remplacement à un service systemd qui a les droits : le binaire est remplacé, le service redémarre.

<CodeBlock lang="bash">
```bash
sudo watchflare-agent update
```
</CodeBlock>

<Shell title="bash" code={`Watchflare Agent v0.40.0

Checking for updates...
Update available: v0.40.0 → v0.40.1

Downloading v0.40.1...
✓ Updated to v0.40.1
✓ Service restarted`} />

Savoir s'il y a quelque chose de nouveau, sans l'installer :

<CodeBlock lang="bash">
```bash
sudo watchflare-agent update --check
```
</CodeBlock>

<Callout type="info" title="Remarque">
  [`agent.conf`](/fr/agent/configuration/), `ca.pem` et le dossier de données restent en place. Seul le binaire change.
</Callout>

## macOS

C'est Homebrew qui met à jour :

<CodeBlock lang="bash">
```bash
brew upgrade watchflare-agent
brew services restart watchflare-agent
```
</CodeBlock>

---

## Mises à jour depuis le tableau de bord (Linux)

Sous Linux, un path unit systemd peut enchaîner tout seul. Page de l'hôte → **Update agent**. Le Hub envoie l'ordre au heartbeat suivant. L'agent télécharge, installe, redémarre. Rien à faire sur la machine.

La page de chaque hôte affiche la version de l'agent. Les versions en retard sont signalées.

---

## Version installée

<CodeBlock lang="bash">
```bash
watchflare-agent version
```
</CodeBlock>

Sortie :

```
Watchflare Agent v0.40.1
```

La même version apparaît sur la page de l'hôte, dans le Hub.

---

## Compatibilité Hub / Agent

Le Hub et l'Agent ont le même numéro de version. Ils sont publiés en même temps. Un agent plus ancien continue de parler à un Hub plus récent d'une mineure à l'autre : les métriques ou RPC inconnus sont simplement omis. Le [changelog](/fr/changelog/) signale un changement incompatible s'il y en a un.

Gardez tout de même les agents à jour : correctifs et nouveaux collecteurs.
