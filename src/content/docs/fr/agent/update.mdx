## Linux

L'agent dispose d'une commande de mise à jour intégrée. Elle vérifie la dernière version via l'API GitHub, télécharge le binaire depuis `get.watchflare.io`, vérifie la somme SHA-256, puis passe la main à un service systemd privilégié pour remplacer le binaire et redémarrer.

<CodeBlock lang="bash">
```bash
sudo watchflare-agent update
```
</CodeBlock>

<Shell title="bash" code={`Watchflare Agent v0.40.0

Checking for updates...
Update available: v0.40.0 → v0.40.1

Downloading v0.40.1...
✓ Updated to v0.40.1
✓ Service restarted`} />

Pour vérifier si une mise à jour est disponible sans l'installer :

<CodeBlock lang="bash">
```bash
sudo watchflare-agent update --check
```
</CodeBlock>

<Callout type="info" title="Remarque">
  La configuration de l'agent ([`agent.conf`](/fr/agent/configuration/), `ca.pem`) et le dossier de données ne sont jamais touchés pendant une mise à jour. Seul le binaire est remplacé.
</Callout>

## macOS

Sous macOS, les mises à jour sont gérées via Homebrew :

<CodeBlock lang="bash">
```bash
brew upgrade watchflare-agent
brew services restart watchflare-agent
```
</CodeBlock>

---

## Mises à jour automatiques (Linux)

L'agent Linux prend en charge les mises à jour automatiques via un path unit systemd. Lorsqu'une mise à jour est déclenchée depuis le tableau de bord du Hub (page de détail de l'hôte → **Update agent**), le Hub envoie une commande à l'agent au heartbeat suivant. L'agent télécharge et installe la mise à jour automatiquement, puis redémarre le service, sans intervention manuelle.

Le tableau de bord du Hub affiche la version actuelle de l'agent sur la page de détail de chaque hôte et met en évidence les hôtes qui tournent avec une version obsolète.

---

## Vérifier la version installée

<CodeBlock lang="bash">
```bash
watchflare-agent version
```
</CodeBlock>

Sortie :

```
Watchflare Agent v0.40.1
```

La version actuelle est aussi visible sur la page de détail de l'hôte dans le tableau de bord du Hub.

---

## Compatibilité des versions

Le Hub et l'agent partagent un seul numéro de version et sont publiés ensemble. Vous pouvez tout de même faire tourner un agent plus ancien face à un Hub plus récent d'une version mineure à l'autre : les métriques ou RPC que l'agent ne connaît pas sont simplement omis. Consultez le [changelog](/fr/changelog/) si une version signale une rupture de protocole.

Gardez les agents raisonnablement à jour pour bénéficier des correctifs et des nouveaux collecteurs.
