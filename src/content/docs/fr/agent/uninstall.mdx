## Linux

La commande `uninstall` est interactive. Elle arrête et retire le service, supprime le binaire, et demande séparément s'il faut retirer le dossier de données, le dossier de config, le fichier de journal et l'utilisateur système :

<CodeBlock lang="bash">
```bash
sudo watchflare-agent uninstall
```
</CodeBlock>

```
=== Watchflare Agent Uninstallation ===

[1/6] Checking permissions...
  → Running as root

[2/6] Removing service...
  → Removed systemd service

[3/6] Removing binary...
  → Removed /usr/local/bin/watchflare-agent

[4/6] Data and configuration...
Remove data directory (/var/lib/watchflare)? (y/N): y
Remove configuration directory (/etc/watchflare)? (y/N): y
  → Removed /var/lib/watchflare
  → Removed /etc/watchflare

[5/6] Log files...
Remove log file (/var/log/watchflare-agent.log)? (y/N): y
  → Removed /var/log/watchflare-agent.log

[6/6] System user...
Remove system user 'watchflare'? (y/N): y
  → Removed user 'watchflare'

=== Uninstallation Complete ===
```

**Ce que contrôle chaque question :**

| Question | Ce qu'elle retire | Répondez N pour… |
|--------|----------------|--------------|
| Dossier de données | Fichier WAL, état des paquets | Garder le tampon de métriques intact |
| Dossier de config | `agent.conf`, `ca.pem` | Conserver les identifiants d'enrôlement |
| Fichier de journal | `/var/log/watchflare-agent.log` | Garder les journaux pour dépanner |
| Utilisateur système | utilisateur système `watchflare` | Le garder si vous réinstallez bientôt |

Répondre **N** pour le dossier de config conserve `agent.conf` et `ca.pem`. Si vous réinstallez l'agent plus tard sur cet hôte avec le même `agent_id` et `agent_key`, il se reconnectera au Hub sans nouvel enrôlement.

<Callout type="info" title="Remarque">
  L'hôte n'est pas retiré automatiquement du Hub après la désinstallation de l'agent. Il apparaîtra comme offline sur la [page Hosts](/fr/monitoring/hosts/). Supprimez-le à la main si vous n'en avez plus besoin.
</Callout>

### Vérifier le retrait sous Linux

Vérifiez qu'aucun fichier ne reste :

<CodeBlock lang="bash">
```bash
which watchflare-agent           # ne doit rien renvoyer
ls /etc/watchflare 2>/dev/null   # ne doit pas exister (si vous avez répondu Y)
ls /var/lib/watchflare 2>/dev/null
systemctl status watchflare-agent 2>/dev/null
```
</CodeBlock>

## macOS

Arrêtez le service et désinstallez via Homebrew :

<CodeBlock lang="bash">
```bash
brew services stop watchflare-agent
brew uninstall watchflare-agent
```
</CodeBlock>

Pour retirer aussi les fichiers de config et de données :

<CodeBlock lang="bash">
```bash
rm -rf $(brew --prefix)/etc/watchflare
rm -rf $(brew --prefix)/var/watchflare
rm -f  $(brew --prefix)/var/log/watchflare-agent.log
```
</CodeBlock>

### Vérifier le retrait sous macOS

<CodeBlock lang="bash">
```bash
which watchflare-agent                              # ne doit rien renvoyer
ls $(brew --prefix)/etc/watchflare 2>/dev/null     # ne doit pas exister
brew services list | grep watchflare               # ne doit rien renvoyer
```
</CodeBlock>

## Retirer l'hôte du tableau de bord

Désinstaller l'agent ne retire pas l'hôte du Hub. Pour le supprimer :

1. Ouvrez la page de détail de l'hôte dans le tableau de bord.
2. Cliquez sur le menu **⋯** → **Delete host**.

Supprimer l'hôte retire de la base tout son historique de métriques, l'inventaire de paquets et les règles d'alerte.

---

## Réenrôler le même hôte

Si vous voulez réinstaller l'agent sur cet hôte sans passer par un nouvel enrôlement :

1. Répondez **N** à toutes les questions de retrait des données/config pendant la désinstallation (Linux), ou sautez les commandes `rm -rf` (macOS).
2. Réinstallez le binaire de l'agent.
3. L'agent se reconnectera en utilisant l'`agent_id`, l'`agent_key` et le `ca.pem` sauvegardés, sans nouveau jeton d'enrôlement.

Si vous avez retiré le dossier de config, vous devrez créer un nouvel hôte dans le tableau de bord et exécuter la commande `register` avec un jeton d'enrôlement neuf.
