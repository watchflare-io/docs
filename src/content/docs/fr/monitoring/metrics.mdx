L'agent collecte les métriques système toutes les 30 secondes et les envoie au Hub. Elles s'affichent en temps réel sur les pages de détail des hôtes et sont stockées dans TimescaleDB pour les requêtes historiques.

<Callout type="info" title="Remarque">
  Certaines métriques affichent **0** sur certains environnements, et c'est attendu. La température n'est pas disponible sur les VM ni les conteneurs. L'IOWait est Linux uniquement. Le disque et le réseau sont omis lorsque l'agent s'exécute dans un conteneur. Voir la colonne Notes de chaque tableau.
</Callout>

## Métriques collectées

<a id="cpu"></a>

### CPU

| Métrique | Unité | Notes |
|--------|------|-------|
| Usage | % | Pourcentage de tous les cœurs logiques |
| IOWait | % | Temps d'attente I/O. Linux uniquement, 0 sous macOS et sur les VM. |
| Steal | % | Temps CPU volé par l'hyperviseur. VM Linux uniquement, 0 sur les hôtes physiques et macOS. |
| Temperature | °C | Hôtes physiques uniquement. Indisponible sur VM et conteneurs. |

### Mémoire

| Métrique | Unité | Notes |
|--------|------|-------|
| Used | octets | Mémoire activement utilisée |
| Available | octets | Mémoire disponible pour les applications sans swap |
| Buffers | octets | Cache buffers du noyau. Linux uniquement. |
| Cached | octets | Page cache. Linux uniquement. |

### Swap

| Métrique | Unité |
|--------|------|
| Total | octets |
| Used | octets |

Les métriques swap sont omises sur les conteneurs.

### Disque

| Métrique | Unité | Notes |
|--------|------|-------|
| Total | octets | Capacité totale de la partition principale |
| Used | octets | Espace utilisé |
| Read throughput | octets/s | Débit de lecture disque depuis le dernier échantillon |
| Write throughput | octets/s | Débit d'écriture disque depuis le dernier échantillon |

Les métriques disque sont omises sur les conteneurs Docker (le disque est partagé avec l'hôte et serait compté deux fois).

### Réseau

| Métrique | Unité |
|--------|------|
| Inbound (RX) | octets/s |
| Outbound (TX) | octets/s |

### Système

| Métrique | Unité |
|--------|------|
| Uptime | secondes |
| Load average 1 min | Aucune |
| Load average 5 min | Aucune |
| Load average 15 min | Aucune |
| Process count | nombre |

### Capteurs de température

Sur les hôtes Linux physiques équipés de capteurs matériels, l'agent collecte toutes les lectures de température disponibles (cœurs CPU, disques NVMe, ventilateurs de châssis, etc.) et les stocke individuellement. Elles apparaissent dans la section **Sensors** de la page de détail de l'hôte.

<a id="time-ranges-and-resolution"></a>

## Plages de temps et résolution

Les graphiques de la page de détail de l'hôte sont disponibles en cinq plages de temps. Les plages plus longues utilisent des agrégats précalculés, pour les performances :

| Plage | Résolution | Source |
|-------|------------|--------|
| **1 hour** | Brut (échantillons de 30 s) | table `metrics` |
| **12 hours** | Intervalles de 10 min | agrégat `metrics_10min` |
| **24 hours** | Intervalles de 15 min | agrégat `metrics_15min` |
| **7 days** | Intervalles de 2 h | agrégat `metrics_2h` |
| **30 days** | Intervalles de 8 h | agrégat `metrics_8h` |

Les agrégats sont calculés automatiquement par les agrégats continus TimescaleDB. Passer à une plage plus longue échange la granularité des échantillons contre une vue plus large.

Votre plage de temps par défaut peut être définie dans **Settings → Preferences**.

---

## Mises à jour en temps réel

Le tableau de bord reçoit les mises à jour de métriques via une connexion Server-Sent Events (SSE) persistante vers le Hub. Il n'y a pas d'interrogation périodique, et les données apparaissent en quelques secondes après l'envoi par l'agent. Chaque cycle de collecte de 30 secondes se reflète immédiatement sur le graphique et sur les jauges de statistiques en direct.

---

## Rétention des données

Chaque table a sa propre politique de rétention, appliquée automatiquement par TimescaleDB :

| Table | Rétention |
|-------|-----------|
| `metrics` (brutes, échantillons de 30 s) | 24 heures |
| `metrics_10min` | 14 jours |
| `metrics_15min` | 30 jours |
| `metrics_2h` | 90 jours |
| `metrics_8h` | 1 an |

Les données brutes sont compressées après 1 jour. Le tableau de bord sélectionne automatiquement la table appropriée selon la plage de temps choisie, sans configuration nécessaire.
