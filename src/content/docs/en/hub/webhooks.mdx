Watchflare can send alert notifications to one or more webhook endpoints in addition to email. Webhooks are configured from **Settings → Notifications** — no environment variables required.

Discord, Slack, and Telegram URLs are auto-detected and receive natively formatted messages. Any other HTTP/HTTPS URL receives a generic JSON payload.

---

## Adding a webhook

1. Go to **Settings → Notifications**.
2. Under **Webhooks**, paste the URL and click **Add**.
3. The endpoint is enabled immediately. Toggle it off to pause delivery without deleting it.

You can add multiple endpoints. Each enabled endpoint receives every alert and resolution notification independently.

---

## Supported services

### Discord

Paste a Discord webhook URL — the Hub auto-detects it and sends a rich embed with a color-coded alert or resolution message.

**URL format:** `https://discord.com/api/webhooks/{id}/{token}`

To get this URL: open a Discord channel → **Edit Channel → Integrations → Create Webhook** → copy the webhook URL.

---

### Slack

Paste an Incoming Webhook URL — the Hub auto-detects it and sends a message attachment with a colored sidebar.

**URL format:** `https://hooks.slack.com/services/{...}`

To get this URL: go to [api.slack.com/apps](https://api.slack.com/apps), create or open an app, enable **Incoming Webhooks**, and add a webhook to your workspace.

---

### Telegram

Paste a Telegram Bot API URL with the `chat_id` query parameter — the Hub auto-detects it and posts a text message to the specified chat.

**URL format:** `https://api.telegram.org/bot{token}/sendMessage?chat_id={chat_id}`

**Step 1 — Create a bot and get the token:**

1. Open Telegram and message [@BotFather](https://t.me/BotFather).
2. Send `/newbot` and follow the prompts.
3. BotFather replies with your bot token — a string like `7123456789:AAF...`.

**Step 2 — Get your chat ID:**

1. Search for your bot by name and send it any message (e.g. `hello`). The bot will not reply — that is expected, it only sends notifications.
2. Open this URL in your browser (replace `{token}` with your actual token):
   ```
   https://api.telegram.org/bot{token}/getUpdates
   ```
3. Find `result[0].message.chat.id` in the JSON response — that number is your `chat_id`.

**Step 3 — Build the URL:**

Combine the token and chat ID:

```
https://api.telegram.org/bot{token}/sendMessage?chat_id={chat_id}
```

<Callout type="info">
  For a **group**, add the bot as a member, then send `/start@{botname}` in the group before calling `getUpdates`. By default, Telegram bots only receive commands (messages starting with `/`) in groups — regular messages are silently ignored. The `chat_id` of a group is a negative number (e.g. `-1937459245`).
</Callout>

### Generic (any HTTP/HTTPS endpoint)

Any `http://` or `https://` URL that isn't recognized as Discord, Slack, or Telegram receives a JSON POST with structured fields.

**Payload — alert event:**

```json
{
  "event": "alert",
  "host_name": "web-01",
  "metric_type": "cpu_usage",
  "current_value": 92.3,
  "threshold_value": 85.0,
  "started_at": "2026-06-08T14:00:00Z"
}
```

**Payload — resolve event:**

```json
{
  "event": "resolve",
  "host_name": "web-01",
  "metric_type": "cpu_usage",
  "current_value": 21.4,
  "threshold_value": 85.0,
  "started_at": "2026-06-08T14:00:00Z",
  "resolved_at": "2026-06-08T14:35:00Z"
}
```

**Payload — test event:**

```json
{
  "event": "test",
  "host_name": "",
  "metric_type": "",
  "current_value": 0,
  "threshold_value": 0,
  "started_at": "2026-06-08T14:00:00Z"
}
```

All timestamps are in UTC RFC 3339 format.

## Managing endpoints

| Action | How |
|--------|-----|
| **Enable / disable** | Toggle the switch next to the endpoint |
| **Delete** | Click the delete icon — this cannot be undone |
| **Test** | Click the **Test** button to send a test event to the endpoint |

<Callout type="info">
  The **Test** button fires a test event immediately, regardless of whether any alert is active. Use it to verify that your endpoint receives and parses the payload correctly.
</Callout>
